## 后续修复状态（2026-10-15）

按用户要求，下面两项P1与长历史诊断P2已由Codex修复并重新模拟。还发现并补齐CLI resume JSONL缺少usage的问题。完整回归139文件/1100项通过，重新模拟12项通过；[修复详情与证据](repair-and-resimulation.md)。下文保留初次发现时的根因，不表示问题仍未修复。

## P1：旧评测入口的模型配置与预算失真

**已确认根因**：`scripts/eval/run.mjs` 从 `configData.models` 读取旧平铺模型目录，当前正式配置使用 `providers.<provider>.models`。`--max-calls` 被解析为 `maxTurns`，实际 argv 仅含 `--max-turns`；报告甚至明确写着 `providerCallLimitEnforced: false`。

**初次影响**：旧 runner 不能可靠选择当前正式模型；轮数可能被误当成实际调用费用上限。历史快照保留为LT01输入；当前主工作区已修复。

**方案**：复用统一模型目录解析或维护独立纯模块；将 `--max-model-calls` 与 `--max-turns` 分开传给 Host/CLI；非法引用明确失败，兼容旧格式。只保留真实得到的 usage/成本字段。

**回归**：新旧配置、同名模型、未知 provider/model、非整数或负数预算、嵌套审批/压缩/重试计数；假服务断言实际16次停止。LT01 外部探针已冻结。

## P1：旧批量评测缺少断点恢复

**已确认根因**：`scripts/eval/run.mjs` 对已存在输出目录直接抛错，records 从空数组开始，未依据已有 taskId/trial 重建待执行集合。

**初次影响**：中断后缺少可靠续跑入口，人工重新运行可能重复已完成 trial，并丢失对累计消耗的理解。历史快照保留为LT02输入；当前由Codex修复并通过离线验收，尚未进行真实模型验收。

**方案**：显式 `--resume`，校验数据集/模型/预算身份；读取已有JSONL并明确处理损坏/冲突；终态（含失败）跳过，待执行trial继续，追加历史并重算汇总。不得恢复成一个新的无预算批次。

**回归**：先完成一个trial后强制中断；恢复只执行剩余trial；检查失败trial不重跑、重复记录去重、损坏输入失败、旧产物哈希不变。

## P2：SDK长历史错误不够直接

**实测**：`long-task-calibration.test.mjs` 的20轮双工具路径，在不设置historyCompaction时失败。最外层为 `CONTROL_ERROR_LOOP`，深层为 `CONTEXT_TOO_LARGE`。启用压缩的同规模路径通过。

**修复后**：同一无压缩路径仍失败，但现在直接对外报告`CONTEXT_TOO_LARGE`、历史压力详情和压缩建议。没有提高历史上限或把失败改为成功。

**适用范围**：通用 Runtime 配置边界；受测 Host 默认配置了摘要，不能据此断言 Host 也会在相同轮数失败。16196/16000是本fixture的估计历史值，不是通用容量常数。

**方案**：在可恢复历史压力与硬超限处分开诊断；在SDK长任务示例默认配置压缩；保留原始错误码并给出操作建议，避免用控制循环泛化错误掩盖根因。

**回归**：无压缩仍明确失败且保存检查点；有压缩时保留原目标、已验收阶段、失败证据与等待问题；不能只验证摘要请求成功。

## P2：质量评估仍需语义和长期证据

**事实**：模拟工具结果和机械文件探针只能证明对应路径。本次外部grader将自动分标记为provisional，并要求人工逐项验收。

**方案**：保留冻结输入、逐请求 usage、工具轨迹和产物哈希；为真实访谈/研究类任务建立事实错误与虚报清单。下一轮如需比较low/high，应在同一任务上配对、多次重复并另行批准费用；不能把本次不同任务的得分差当模型优劣。

**回归**：空文件、无来源报告、仅自称检查通过、Runtime成功但没有业务产物都不能得到passed。缺失价格和usage必须显示未知。
