# 基于本轮真实证据的优化顺序

本轮已经停止在93/96次调用，没有为失败样本追加额度。下一步优先用本轮轨迹和离线模型复现；本文件是建议，尚未实现这些新修复。

## 1. P1：让计划适合剩余实际调用额度

涉及：`packages/server/src/model-budget.ts`、`task-controller/program.ts`的plan/dispatch/progress-review，以及Host生成的模型输入。

- 从可信ModelAttemptBudget暴露limit/used/remaining，不能只使用controller.usedTurns估计；后者不完整覆盖独立审批及异常worker。
- 对计划计算最低执行/验证开销，保留最终验收额度。LT01/02/04的5阶段计划在16次预算下已很紧张，实际还加入调查与纠正。
- 合并单独调查与第一项实现；研究任务先生成可核对的MD骨架，边查边写；约束留在全程执行规则中，避免单独规划“禁止提交/禁止外部模型”阶段。
- 额度临近保留值时生成可恢复检查点与明确未完成项，不偷偷另开run。

验收：离线复现本轮5阶段/16次输入，减少规划和调查开销，至少留下可执行的核心产物；总调用不超过16，失败证据不变成通过。

## 2. P1：补齐异常worker结算与依赖证据复用

涉及：`task-controller/program.ts`的onJoin、workerCompletion、阶段输入；`checkpoint.ts`。

- 失败outcome也收集已结算模型effect、文件操作、工具结果和草稿receipt；保持失败状态。
- 给下阶段提供已读窗口与hash，允许检索完整证据。明确区分“已有内容可用”和“只有文件名/摘要存在”。
- 相同窗口重读需说明证据不足或失效原因；新页与相关文件更新仍属有效进展。

验收：预算耗尽/取消/异常/正常blocked四条路径的阶段计数与根账本一致；已通过阶段不重跑；LT05同类文档任务减少重复读。

## 3. P1：防止把初始草稿当完整文件提交

涉及：`editing.ts`、ReAct工具说明、阶段执行策略。

- 本轮LT01/03均只有begin、inspect、commit，没有append，留下不闭合JS。先用该轨迹做离线回归。
- 成功begin/append已返回revision/bytes，正常流程无需inspect；把草稿状态和已验证文件分开呈现。
- 为提交后的语法检查保留预算；选择合适的新文件工具，避免小模块也走多轮staging。可评估受限的新文件整段写入接口，但必须保留字节上限、不覆盖和路径边界。
- 不能让通用文件工具宣称“语义完成”；具体语言的检查成功才构成代码验收证据。

## 4. P1：修正评估脚本后再测访谈恢复

涉及：`scripts/eval/long-task-lib.mjs`的interviewAnswer、冻结grader。

- 用LT06实际选项测试明确v2路径和多文件报告布局；basis必须对应实际value。
- 未识别选项等待需求方回答，不自动猜测或取消；用户禁止的覆盖选项不应被建议。
- 负向探针先确认合法输入可执行，再校验指定错误及副作用；文件存在不能代替实际diff或完整产物。

完成上述离线回归后，再另行安排有明确费用上限的真实复测。本轮不增加样本，不把受干预的第6例算作Pulse失败，也不宣称冷恢复已通过。

## 验证原则

保留本次93条HTTP请求/usage、六个Runtime快照及产物。用相同任务做修复前后比较时，明确是下一轮，不能覆盖本轮结果。low/high各三个不同任务的单次结果不能推出档位优劣。增加预算是否改善交付尚未知，不能作为已经验证的方案。
