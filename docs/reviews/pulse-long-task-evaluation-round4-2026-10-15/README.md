# Pulse 长任务第四轮真实评估

执行日：2026-10-15。模型：deepseek/deepseek-flash。

## 结果

DeepSeek在本轮可以正常生成：299次请求全部有HTTP 200完整响应和usage，未记录网络错误。六例均已实际执行：**完整通过0例，部分完成4例，失败2例**。这六个不同任务不能用来推算稳定成功率或low/high优劣。

本轮只测试、独立验证并写报告，没有修改Pulse产品代码。374个驱动源码/编译文件及冻结验收脚本哈希无变化；历史三轮记录保留。

## 最值得先处理的问题

1. 草稿begin/inspect及同窗口读取仍形成无效循环，64次也可能零交付。
2. 验证模型的长错误输出进入纠错指令，触发2KB限制；模型虚构的工具转录也不能充当证据。
3. 恢复实现没有继承历史消耗；独立假CLI探针已经复现超预算仍派发。
4. 文档关键词检查会漏掉错误承诺，访谈也会重复问已答维度。
5. 验收器误把hold/execute最终确认当未知问题；这是测试适配缺陷，不能归因于Pulse丢会话。

详见[问题清单](findings.md)与[优化方案](optimizations.md)。这些方案尚未实施。

## 调用与成本

- 实际请求 **299/384**；每例20、46、64、64、64、41，均不超过64。审批和压缩等包含在总数内，失败后没有加试。
- HTTP合计输入 **5,505,293 tokens**，输出 **574,469 tokens**；输入中的缓存4,058,112、输出中的推理490,059均为子集，不重复相加。
- 每例外部attempts、预算文件和Host持久账本一致。前五例还有最终Host usage可对账；LT06没有完整Host终态usage，但41个HTTP usage全部保留。
- 没有冻结价格或完整账单，**金额未知**。详见[用量审计](usage-audit.json)。

## 验证边界

真实调用走生产Host/Runtime SDK及内置技能，未做完整交互终端方向键/Enter验收。LT04使用冻结官方文档摘录，未新增联网研究。LT02额外使用假CLI验证恢复控制流，并不代表业务产物质量通过。
