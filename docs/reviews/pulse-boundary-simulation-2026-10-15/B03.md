# B03：提交后文件被用户编辑，恢复过程再次提交原草稿

状态：**复现问题（未修复）**。优先级：P1。

## 场景与预期

不能用旧hash回执证明当前文件仍等于旧草稿。

## 实际观察

首次commit成功后用户修改目标，再commit仍返回committed=true和旧contentHash；文件实际hash不同。用户修改完整保留。

本场景使用的验证层级：False stale receipt; user content is NOT overwritten。全部模型回答由脚本提供，没有向真实用户发题，也没有调用真实模型。

## 优化方向

幂等commit也核对当前目标hash；已改变则返回DRAFT_TARGET_CHANGED，并使旧回执不能充当当前文件验收证据。
