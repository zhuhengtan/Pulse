# Pulse LT01：v14 lane 连续性修复后真实验收

日期：2026-10-16。结论：**执行流程走完，功能仍未完整通过独立验收**。本轮只进行一次真实 `deepseek/deepseek-flash`（low）运行，11:12:12–11:15:23，北京时间，约 3 分 12 秒；之后全部为离线检查，没有追加模型调用。

## 结果

- 25 次请求全部 HTTP 200，5 个阶段均完成，辅助模块、runner、README、10 项自测全部交付。Pulse 报告 `taskOutcome.status=accepted`。
- 全程同一个 `lane-1`，历史从 0 增至 24 条，所有阶段只尝试一次；没有重规划。三个不同本地检查各执行一次，没有同身份检查重复执行。
- 独立原评分 **8/14**。三个正向入口因评分器要求未约定报告字段名而误判，补充语义核查均通过；三个非法预算组合是真实失败，不能忽略。
- 冲突别名、重复 flag、缺值 flag 仍启动了假 CLI；自测把“冲突时取前者”固化成通过断言，Host 的最终验收未发现。这是本轮不能完整通过的主要原因。
- 用量 **945,031 token**（输入 914,002、输出 31,029），比上一轮 848,323 增加约 11.4%。调用次数从 38 降至 25，交付范围扩大，但不能宣称成本降低。

## 新观察

同 lane 的阶段候选引用没有正确隔离：s2/s3 沿用 s1 的 `result-17`，s5 沿用 s4 的 `result-49`，最终汇总重复输出 README 阶段正文。另有一批“未读分页＋搜索”被整批编辑门禁拦截；本轮随后完成了编辑，但分页保护存在混合批次缺口。

历史持续增长，本轮没有触发压缩，最终请求输入达到 69,838 token；交付清单本身均小于 1.4 KB，并不是主要膨胀来源。模型还重新请求了三份已暴露的历史读取证据。
