# Pulse 自测通过但错误验收：修复与本地验证

日期：2026-10-16。本轮由 Codex 直接修复，真实模型调用 **0**。结论：已增加 Host 独立验收门禁，并以 round8 原始产物离线验证能拒绝误接受；尚未进行修复后的真实模型重跑。

## 根因

round8 的自测只检查了部分行为，还把冲突预算取前者写成正确断言。最终模型验收据此报告全部通过；Host 当时只核对引用、工具结果和文件新鲜度，没有一份不可由候选改写的入口断言清单。独立探针随后发现冲突别名、重复参数、缺值参数仍到达 fake CLI。

## 修复

- 新运行使用控制器 **v15**；v5–14 仍保留恢复支持，不静默升级历史运行。
- SDK 调用方可通过 `acceptanceChecks` 声明可信 Host 工具、固定参数、原验收项和精确断言 ID。检查描述及参数在运行前复制到 TaskRecord，模型不能替换；该工具也从实现循环的允许列表中排除。
- Host 在最终模型验收前实际执行检查。每个冻结断言须且只须出现一次，并有明确布尔结果；失败判 `not_met`，缺项、重复、拒绝、取消、无效回执判 `unverifiable`。模型的“passed”不能覆盖这些状态。原始 ResultRef、错误原因码和已完成阶段保留，不自动开新 run 重试。
- 对明确要求非法 CLI 预算/参数报错的任务，缺少有效入口、非法值、冲突、重复、缺值的独立覆盖时，不再仅凭候选自测判完成，而明确报告 `INDEPENDENT_ACCEPTANCE_REQUIRED`。
- LT01 评测入口已在运行前装配可信适配器，实际检查 helper 字符串接口、新旧配置、真实 runner 的正反向参数入口，并使用 fake CLI 记录是否发生调度；候选自己的测试或评分器不能替换这些断言。检查在另一份本地副本执行，提供可信编译依赖，并保存源码/环境检查回执。
- 评分器兼容语义等价的 `maxModelCallsPerAttempt` / `maxModelCallsPerTrial`。如果两者同时出现，必须一致；实际转发值、模型身份、artifact 评分、负向入口断言仍严格检查。历史 round8 的 **8/14** 不改写。
- 冷恢复读取原 TaskRecord，即使新 Host 的默认检查配置为空，仍保留原契约。检查与用量无关，不增加模型调用。

## 验证边界

这次修复防止“没有足够证明却宣称完成”，并未证明任意自然语言任务都正确。可信验收工具仍需由 Host/项目集成方提供；对识别到的 CLI 异常参数任务，如果没有这种适配器，会明确待验收，而非自动创造通过证据。LT01 适配器已经接入评测 harness。fake CLI 证明参数转发与错误前置拒绝，不能证明真实 CLI 内部模型预算执行。

未进行真模重跑、交互 CLI 键盘验收、安装包或跨平台验收。上一轮发现的阶段正文串用、混合分页门禁和上下文成本问题不属于本轮验收误接受修复，仍有后续工作。
