## 为什么仍未完成

### 1. 压缩响应中的工具提议被当成了执行事实（P1）

第 22、29 次请求均是 `$compact-summary`，模型都返回了工具调用，摘要正文为空。第 29 次提议创建 `scripts/eval/resume-e2e.test.mjs`。压缩步骤没有执行该工具，因此该文件不存在；第 30 次工作请求却把它列入了：

```sh
node --test scripts/eval/run-resume.test.mjs scripts/eval/resume-e2e.test.mjs
```

`run-resume.test.mjs` 实际存在，`resume-e2e.test.mjs` 不存在。工具提议没有被执行是正确边界；缺陷在于无有效正文的响应仍被采纳为历史摘要，后续模型未核对落盘回执。

建议：摘要请求禁止工具调用，校验非空摘要；不把失败或工具提议作为成功压缩。保留原历史，以有界纠正或检查点收尾处理。后续执行文件须有写入回执或当前文件证据。

### 2. 审批拒绝同时阻断了最终验收报告（P1）

`effect-66` 的命令包含不存在的文件，进入审核。没有本地 reviewer，原生人工确认被评测拒绝，控制器把第四阶段标为 `APPROVAL_DENIED`。冻结只读检查 `effect-68` 正常运行，得到两项失败。

随后 `effect-69 / verify-task-llm` 在发送前被 `assertRunCanContinue` 的旧 `AI_APPROVAL_UNAVAILABLE` 拦截，未产生第 31 次 HTTP 请求。实际预算视图已经是 30/32，工作停止、验收配额可用；本次未完成的直接异常不是预算上限本身。

建议：继续禁止被拒操作和等价重试，纯最终报告/冻结只读验收采用独立收尾规则。缺失文件可以先给出确定性诊断，减少无效审核。不能把本次人工拒绝描述成对有效操作的误拒绝。

### 3. 最终报告没有投影已知的独立失败（P1）

`task-controller.json` 已保存 `evaluation-resume-contract: failed` 及两项断言详情，但 `task-outcome.json` 的八项标准仍全部为 `unverifiable`，聊天最终汇总也未列出这两项失败。本轮已消除旧阶段正文拼接，当前阶段终态也是 blocked；失败证据到业务结果和用户报告的映射仍有缺口。

建议：异常收尾复用已有验收结果，已证明失败的标准应为未满足；明确列出失败断言。不要重复执行检查或把已知失败降为未知。

### 4. 候选实现仍漏掉两项恢复语义（P1）

- `run.mjs` 将原始历史行直接纳入报告：重复终态使 `tasksRun=3`，实际唯一 trial 为 2。去重待执行列表并不等于去重汇总。
- `consumedCostUnknown` 在恢复后仍置为 false：独立测试观察到两次调用，应只有一次。未知费用状态未继承。

本轮 token 消耗已经从历史恢复，对应探针通过。主工作区原先修好的 runner 没有被替换；以上缺陷属于模型从原始输入重新生成的候选。上一轮本地修复副本的 9/9 不能当成本轮模型产物的验收结果。

### 5. 工具发现与工作阶段权限不一致（P2）

第 23 次请求提出 `evaluation-acceptance.resume`。请求的工具发现信息包含它，工作阶段的允许列表却过滤 Host 冻结验收工具，因此没有实际执行。真正的独立检查在结束时由 Host 执行。

建议：让工具发现与当前允许列表一致；仅 Host 可调用的检查不应作为可调用工具暴露给工作模型。逐请求记录要区分“提议”和“实际执行”，不能只数 HTTP 中的工具名。

### 6. 候选测试仍不足以覆盖业务缺陷（P2）

真实运行中模块测试 10/10 通过。运行停止后，Codex 在**新的离线副本**中执行两个实际存在的测试文件：模块 10/10、端到端 4/4 通过，未改候选文件、未调用模型。它们仍未验证重复终态的报告去重和未知费用继承，不能替代九项独立验收。
