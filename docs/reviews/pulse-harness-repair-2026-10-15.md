## 规模复测

以下是在本机 Node 24.1、无 provider 条件下的确定性测量。调度步骤没有长模型请求或外部工具成本；不能解读为模型完成 10000 步真实开发任务。

| 实际调度步骤 | 执行耗时 | 恢复耗时 | 累计快照写入量 |
|---:|---:|---:|---:|
| 100 | 118 ms | 6.5 ms | 155289 B |
| 1000 | 890 ms | 5.7 ms | 1699243 B |
| 10000 | 8343 ms | 6.0 ms | 15916833 B |

对照本轮修复中的中间版本，10000 步累计快照写入从 351832644 B 降到 15916833 B，约减少 **95.5%**；执行耗时从 29.4 s 降到 8.3 s。进程累计峰值 RSS 从约 451 MB 降到约 206 MB；这是进程峰值，不能当作单个缓存的大小或硬上限。

[调度规模明细](../../.pulse-dev/harness-repair-20261015/scale-confirmed/results.json)与[历史结果规模明细](../../.pulse-dev/harness-repair-20261015/scale-final/results.json)分别记录。10000 个约 1 KiB 历史结果的活跃快照约 2.86 MB，外置数据及快照共约 13.8 MB，恢复约 272 ms，读取指定 ResultRef 才加载正文。逐文件 fsync 的首次历史导入仍较慢（本次约 66.5 s），没有隐藏这个成本或提高存储护栏。

## 本轮途中发现并修复的问题

1. 检查清单读取初版传入超过文件工具支持的窗口，导致 INVALID_READ_RANGE；改为遵守原 1 MB 边界，没有放宽文件工具。
2. 异步保存尚未涵盖的新结果被提前标记为外置，造成 RUNTIME_RESULT_NOT_FOUND；只外置已实际保存的引用。
3. 恢复后的纯步骤未加载 lane 状态、所用 Global 版本及嵌套 ResultRef；在纯步骤执行前构建所需正文闭包。
4. 自动事件归档触发 FactInbox 克隆时漏传去重归档，阻断后续派发；保留同一归档身份。
5. 事件正文归档后，其元数据仍回填到活跃存储；调整归档完成后的移除顺序，并保留历史页。
6. 静态依赖分析漏掉 side-effect import，且 `/var` 与 `/private/var` 别名影响范围判断；补齐导入形式并统一真实路径。
7. DSML 测试用消息中出现 `bytes` 判断文件已写，可能被工具 schema 误导；改成检查实际文件回执。旧测试直接读内联正文的部分改为通过结果存储恢复同一正文，没有删除业务断言。
8. SDK 原有恢复兼容检查会推迟到执行入口；新增的构建授权回归发现空运行恢复尚未立即拒绝未知指纹，已在 restore 返回前核对指纹，程序注册的原有延迟语义保持。

独立 Node 测试首次在受限环境触发原生异步断言；允许本机隔离测试服务后 25/25 通过。大日志验收脚本初次导入路径错误，修正后才执行了实际命令。失败日志与中间规模数据均保留。

## 使用入口与限制

配置、需求附件、日志分页、构建授权及旧草稿认领见 [使用说明](../harness-reliability.md)。

- 本次验证为本机源码、编译产物、本地模拟及真实本地子进程；没有真实 DeepSeek 验收、正式服务验收、跨平台或发布验证。
- 检查依赖清单覆盖静态 JavaScript 本地导入及保守项目源码范围；任意动态读文件、远程服务状态和完整多语言依赖图仍不保证自动识别。
- token/费用限额控制后续准入，已开始的一次响应可能超额；provider 不报告费用时严格策略停止，配置价格估算与实际报告费用分开。
- 30/100 决策验证的是投影与保留机制，没有测得真实模型的约束落实率。10000 步规模检查也没有覆盖 10000 个超大 LLM 请求的历史。
- 保留现有未提交改动和历史数据；没有把本地通过描述成正式环境已更新。
