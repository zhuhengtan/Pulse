# 当前控制器与自主恢复

Pulse 尚处于未上线阶段，Host 使用一个当前任务控制器。`legacy` 配置值和旧调用标签仅按当前策略解释，不选择旧行为。Runtime SDK 本身的程序兼容契约保持独立。

## 执行和失败恢复

任务始终保留原始需求、冻结检查和累计模型预算。失败先归一化为 `FailureRecord`，按输入纠正、补验、环境修复、兼容模型切换、缩小请求、授权范围内替代方式、未知操作对账或产物修正处理。

控制器通过 `RecoveryAttempt` 保留失败事实、后续处理方法、实际工具证据和进展判断。单次工具失败不会直接宣告整个任务失败。已完成交付继续保留；补验失败不能成为重新实现已完成模块的理由。失败的原始检查始终保留，必须通过当前检查才能验收。审批守卫按原生操作名称和规范化参数保留拒绝，不再因为一次拒绝而封锁整个任务；其他方法仍经过原有权限和审批。模型调用始终由累计预算账本决定是否准入。

恢复没有固定三次上限。新的已结算证据可以继续推进；修改计划措辞、重复查询状态和更换回执 ID 不代表进展。连续八个恢复周期无新证据会保留检查点并等待帮助。用户取消、原预算不足和需要用户决定仍保持明确边界；换方法不能扩大权限或降低原验收标准。

模型反复生成无效依赖图时，当前控制器会退回只覆盖原始未满足条件的单一交付阶段；不会执行被拒绝计划中的操作。历史摘要在有限重试后仍不可用时，使用原始任务、阶段状态、实际人工回答和证据引用组成明确标注的事实检查点。它不产生验收结论，也不执行摘要中的工具提案。通用 Runtime SDK 未配置该回退时仍保留原有失败行为。

## 更新后接管

恢复先保存原快照及接管日志。当前实现重新绑定控制程序和工具契约，保留原问题、回答、产物、操作身份及预算。代码、策略和工具指纹变化用于诊断，不再要求用户确认精确构建对。

已挂起的问题先正常收取答案，再进入接管诊断。更新前的模型提案不会因此自动发起新操作。未知副作用继续走 Runtime 对账流程，不能直接重发。缺失工具交由当前执行器返回实际错误，再选择可用替代方式。

## 证据与服务

`StepContext.results.list()` 返回当前 Lane 可见且属于同一 Agent 的结果元数据，遵守可见范围和隐私标签。Host 从完整回执生成索引；验收模型选中的引用不再决定是否启用来源或视觉审计。质量验证的预算预留同样从实际成功工具记录判断。

`shell.start` 增加 `lifetime: 'command' | 'service'`，默认 `command`。持续预览/服务使用 `service`：Host 用实际沙箱强制工作区只读，使用隔离 home 与 scratch。应先完成编译等写入，再启动服务。只有这种服务在明确的用户服务要求和原生 HTTP 就绪证据下，才可与验收并存。普通命令、冷恢复后的未知进程和未确认 stdin 仍阻止验收。

## 运行健康投影

任务进度携带只读 `RunHealth`：执行、验收、环境状态、恢复次数、失败码及下一步动作。Web、Electron 和 CLI 观察同一任务进度；客户端重连使用带序号的既有状态同步，不重发操作。环境未知时明确保持 `unknown`，不把任务执行中当作所有依赖健康。

## 验证边界

普通 CI 使用 Mock Provider 和隔离数据目录。自主换方法、更新接续、证据遗漏、服务写隔离和重复操作分别验证。离线测试不能证明真实 Provider 的任务完成率、真实 Electron 行为或其他平台的安装更新质量；这些结果需要独立真实评测和设备验收。
