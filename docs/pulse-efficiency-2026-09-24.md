# Pulse 自开发效率优化与能力保留验证（2026-09-24）

本轮原则：减少重复上下文、重复工具执行和无效整轮重试，不降低模型、调用预算、审批或验收标准。
当前开发构建已实现下述机制；本机真实 DeepSeek 小型修复和续跑样例通过。
这不等于所有任务的质量无回归证明，也不是三平台或完整质量评测验收。

## 实现

- 控制器 v6 显式提供原目标、全部验收条件、原对话（包含早期方案）、用户纠正、阶段依赖、历史阶段和剩余预算，避免再附加重复的整个 global/history/lane。持久化历史不因投影而删除；旧 v5 快照仍可加载。
- `task.evidence`、`task.history`、`task.conversation` 分页获取保留的信息。窗口按 JSON UTF-8 字节限制，不拆分正常分页中的 Unicode 字符；子 Lane 不能读取根会话，私有或带隐私标记的结果不能借公开检索外泄。
- 简单“继续”可在工作区清单和依赖文件哈希仍一致时复用已通过的文件阶段。新运行生成新的 ResultRef，携带原始工具证据；不会把旧 ID 或一句“通过”当成新证明。缓存可连续继承。
- Shell 检查、外部调用、缺失/过大证据、无法核验的工作区及无效依赖不自动复用；需要新验证时照常执行。更具体的新指令重新规划。
- 已通过依赖阶段的工具证据可直接用于后续执行与阶段验收，不必重新读取来制造本阶段引用。最终验收保留报告正文及明确声明的预期失败证据。
- 最终验收误引历史 ID 时，提供一次有界纠错，仅重做验收。仍占用原总预算；再次错误或缺乏真实证据时拒绝通过。
- `operations.json` / `task.audit` 提供本运行工具、路径、结果引用、命令退出码的归因。它不是完整文件系统审计，不会把既有脏改动归给 Pulse；Shell 副作用仍需审查。

## 真实修复对照

两边在当前项目下处理相同临时样例、同一提示词和同一配置模型 `deepseek-flash`，最多 24 次模型轮次。
任务：只修复 `sumPositive`，保留接口和测试，运行相同的三项测试并中文报告，不提交、不推送。
每轮从相同错误实现开始，外部再次运行测试并逐字检查测试文件未被修改。
旧构建取自本轮开始前已有的本地开发包；没有发布任何版本。

| 构建/试验 | 输入 token | 输出 token | 耗时 | 外部测试 | Pulse 整体验收 |
| --- | ---: | ---: | ---: | --- | --- |
| 优化前 | 110,882 | 7,115 | 49.3 秒 | 3/3，通过 | 未通过 |
| 第一版优化 | 98,756 | 11,262 | 66.6 秒 | 3/3，通过 | 通过 |
| 依赖证据修正后 | 74,077 | 7,776 | 45.5 秒 | 3/3，通过 | 未通过：历史引用 |
| 引用纠错后 | 78,030 | 10,294 | 60.3 秒 | 3/3，通过 | 未通过：验收缺少报告及预期失败证据 |
| 最终构建 | **81,709** | **6,814** | **40.1 秒** | **3/3，通过** | **通过** |

最终样例相比旧样例输入减少 26.3%、输出减少 4.2%、耗时减少 18.6%。
最终运行实际触发了一次引用纠错，仍在预算内完成验收，没有为引用错误重跑整个开发任务。
但旧样例整体验收失败，两者完成质量不同；每个构建只有一个顺序样本，模型存在波动，不能把这些数字当作稳定收益保证。
耗时包含 CLI 启动，修复样例还包含外部复验开销；不是累加 Provider duration 来冒充墙钟时间。

## 真实续跑

只读检查两个小文件并给出依据。初次使用 5 次模型调用、2 次文件读取，后续各为 1 次哈希验证工具和 1 次最终模型验收。

| 运行 | 输入 / 输出 token | 耗时 | 结果 |
| --- | ---: | ---: | --- |
| 首次检查 | 16,029 / 1,726 | 13.2 秒 | 通过 |
| 第一次续跑 | 2,474 / 513 | 3.6 秒 | 通过，无重复读文件 |
| 第二次续跑 | 2,513 / 831 | 5.4 秒 | 通过，无重复读文件 |

之后修改工作区再次续跑，缓存失效并重新执行，符合预期；这一故障演练暴露了后续阶段误拒依赖证据的问题。
失败和后续通过的运行均保留在 JSON 中，而不是算成缓存命中。
该问题的修正由依赖证据单测以及最终真实修复中的报告阶段验收共同验证。

## 验证与剩余边界

- `pnpm check`：107 个测试文件，741 项通过；其中效率测试涵盖缓存失效、连续继承、原约束保留、历史检索权限、Unicode 分页、符号链接拒绝、依赖证据及一次引用纠错。
- Shell、审批、取消、恢复、持久化的原有回归保留并运行；本机端口和 Shell 沙箱测试在允许相关权限的环境执行。
- 本轮共 10 次真实运行，累计输入 589,365、输出 55,046 token，包含失败试验。Provider 未返回费用，金额未知。
- 没有降低模型、缩小原调用预算、跳过必要测试，或为了通过验收放行未知引用。没有自动提交、推送、发布或安装服务。
- 尚无多轮统计意义的整体提速结论，也没有新 Windows/Linux 实机结果。大项目超过保守缓存界限会正常执行，缓存收益可能较小。
- 大型 Shell 的完整副作用归因、外部服务结果的安全跨运行缓存不在本轮完成范围。
