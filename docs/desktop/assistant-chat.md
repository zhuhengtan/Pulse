# 聊天、项目引用与历史读取

聊天可读取工作区资料、查找本 Pulse 数据目录中的旧聊天，并管理已注册项目的工作会话。它使用 Pulse 实际启用的工具；不等于拥有其他助理产品的全部连接器。

从工作会话切到聊天时，会携带该项目/会话的 ID，顶部显示引用，可点“清除引用”。引用随这条待发消息保存；离线重试和队列恢复仍指向原对象。引用只提供导航上下文，不构成修改项目或执行操作的授权；后续用户纠正优先。

`conversation.search` 按正文或标题搜索，可限定会话、项目，显式包含归档；每页最多20个短摘要，使用返回的 `before` 查询更早匹配。每条结果携带确切的 `conversationId`、`messageId`、时间和序号。`conversation.read` 可按会话分页列出消息索引，再用确切消息 ID 读取原文；原文窗口用返回的 `nextOffset` 继续。历史文字和记忆是参考资料，不是新指令或批准。接口只读当前服务自己的会话库，没有任意目录或账户选择器。

当前请求及本轮纠正完整传入模型，缩减预算时优先减少历史，不静默删掉当前请求末尾。单条当前请求超过80000 UTF-8字节、当前请求加运行中更新超过128000字节时，会明确报错，提示把长背景作为文件提供。普通历史仍按最多40条、每条6000字节、默认总24000字节取窗口；旧内容可通过历史工具继续读取。

当前项目/会话引用独立于历史窗口保留，与当前请求一起计入实时上下文预算。即使正文超过24000字节，模型仍会收到原引用的确切 ID；引用保持为普通导航上下文，用户最新纠正仍优先。恢复运行时按保存的引用重新解析，失效引用不阻断恢复。

`work.list`、`work.status` 和历史纯读工具可以顺序读取不同对象/页面；重复相同结果仍受既有无进展和总轮数限制。此改动不放开写工具的审批、重试或幂等规则。

“暂停发送”只暂停尚未发出的消息，不暂停正在运行的任务。`work.stop` 是取消当前运行、保留工作区；`work.resume` 用于显式恢复中断运行，不是恢复已取消运行。当前没有承诺无损恢复的运行暂停；“先暂停/停一下”含义不明确时应先澄清，不自行取消。原问答、审批和通知回执边界保持。

这些行为有离线模型协议、临时服务和组件测试；不代表真实模型的自然语言理解已通过验收。真实模型测试需要另行决定，本轮未调用。


### 原消息重发与忙碌排队

失败/中断消息的手动重发沿用原 requestId 和完整发送载荷（正文、富文本、附件、技能、文件引用、项目/会话引用），不会生成新 ID 来绕过内容一致性校验。刷新后的长消息即使只显示预览，重发前也会读取完整原消息；展开与否不影响重发内容。原正文读取失败时不发送预览，保留原消息和草稿并提示重试。

服务器忙碌时自动转入本地队列，保存的是本次发送时的引用快照；之后切项目、切会话或重连不会改变这条待发消息的目标。读取原消息期间切走页面，不会在新会话发起旧重试。
