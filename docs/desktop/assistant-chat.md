# 聊天、项目引用与历史读取

聊天可读取工作区资料、查找本 Pulse 数据目录中的旧聊天，并管理已注册项目的工作会话。它使用 Pulse 实际启用的工具；不等于拥有其他助理产品的全部连接器。

从工作会话切到聊天时，会携带该项目/会话的 ID，顶部显示引用，可点“清除引用”。引用随这条待发消息保存；离线重试和队列恢复仍指向原对象。引用只提供导航上下文，不构成修改项目或执行操作的授权；后续用户纠正优先。

`conversation.search` 按正文或标题搜索，可限定会话、项目，显式包含归档；每页最多20个短摘要，使用返回的 `before` 查询更早匹配。每条结果携带确切的 `conversationId`、`messageId`、时间和序号。`conversation.read` 可按会话分页列出消息索引，再用确切消息 ID 读取原文；原文窗口用返回的 `nextOffset` 继续。历史文字和记忆是参考资料，不是新指令或批准。接口只读当前服务自己的会话库，没有任意目录或账户选择器。

当前请求及本轮纠正完整传入模型，缩减预算时优先减少历史，不静默删掉当前请求末尾。单条当前请求超过80000 UTF-8字节、当前请求加运行中更新超过128000字节时，会明确报错，提示把长背景作为文件提供。普通历史仍按最多40条、每条6000字节、默认总24000字节取窗口；旧内容可通过历史工具继续读取。

当前项目/会话引用独立于历史窗口保留，与当前请求一起计入实时上下文预算。即使正文超过24000字节，模型仍会收到原引用的确切 ID；引用保持为普通导航上下文，用户最新纠正仍优先。恢复运行时按保存的引用重新解析，失效引用不阻断恢复。

`work.list`、`work.status` 和历史纯读工具可以顺序读取不同对象/页面；重复相同结果仍受既有无进展和总轮数限制。此改动不放开写工具的审批、重试或幂等规则。

“暂停发送”只暂停尚未发出的消息，不暂停正在运行的任务。`work.stop` 是取消当前运行、保留工作区；`work.resume` 用于显式恢复中断运行，不是恢复已取消运行。当前没有承诺无损恢复的运行暂停；“先暂停/停一下”含义不明确时应先澄清，不自行取消。原问答、审批和通知回执边界保持。

这些行为有离线模型协议、临时服务和组件测试；不代表真实模型的自然语言理解已通过验收。真实模型测试需要另行决定，本轮未调用。


### 原消息重发与忙碌排队

失败/中断消息的手动重发沿用原 requestId 和完整发送载荷（正文、富文本、附件、技能、文件引用、项目/会话引用），不会生成新 ID 来绕过内容一致性校验。刷新后的长消息即使只显示预览，重发前也会读取完整原消息；展开与否不影响重发内容。原正文读取失败时不发送预览，保留原消息和草稿并提示重试。

服务器忙碌时自动转入本地队列，保存的是本次发送时的引用快照；之后切项目、切会话或重连不会改变这条待发消息的目标。读取原消息期间切走页面，不会在新会话发起旧重试。

### 任务结束回复

受任务控制器管理的工作结束后，服务端统一生成最终回复，桌面、H5、CLI、保存后的聊天记录和运行结果使用同一份文字。默认用自然的两三句话说明结果，必要时补充验证或实际阻塞，不再直接拼接阶段 ID、验收编号、证据引用和各阶段小结。普通助理聊天不增加这次归纳调用；历史消息不自动重写。

归纳最多使用一次实际 Provider 请求，计入原运行的 `completion-summary` 预算与用量；不调用工具、不重做工作、不改变验收结论。送给归纳模型的请求只包含用户目标和用户追加输入（含计划修订意见）；goal recovery 等宿主控制提示不进入该请求，因此其中的阶段编号和 Fix 字样不会放宽内部编号过滤，也不会把说明类回答误判成编码任务。普通单词即使被用作阶段编号，也不会整段删除正文；只有带结构的内部编号会被掩去。取消运行、额度不足、生成失败、返回工具请求或输出不完整时使用事实兜底。未完成、失败和无法验证的回复按已结算状态渲染：当前阻塞是权威事实，把原因写成历史记录或改口称全部完成都不能发布。计划可以给同一交付身份的后一阶段写明它替代哪个阶段。这个关系进入任务状态、恢复后的控制器和最终回复投影。预算收拢、准备阶段合并和恢复编号改写都不会把仍被替代的交付与另一身份合成一个阶段。未声明身份不算同一交付，混合结果也不会继承组里另一个身份。这些变换之后，实际执行图再经过同一套计划校验。依赖、目标措辞和数值都不会建立替代。无法证明替代，或替代关系成环时，相关原文都保留并用各自目标区分。正文和其中的来源链接使用同一组当前交付，被替代正文里的旧链接不会再附上。原文后面追加的句子，以及写在链接可见文字里的指令，都不会发布。只有当前交付原文里已有的链接和已证明的文件链接可以留在正文之外。

完整原报告保存在运行目录的 `completion-report.json`，原 Runtime 结果、验收记录和检查点保留。这份审计副本写入失败时仍发布已经确定的最终回复。`completion-reply.json` 记录归纳尝试和选定回复。重复读取或崩溃后的恢复不再花费一次请求；输入指纹变化时也重新核对已保存回复：它必须就是当前有效交付，不能只是把当前原文夹在旧结论里。互相矛盾时改用当前事实兜底。固定运行标识只避免重复插入；已保存的旧 final 与当前结论不一致时，改写该条消息。分页和单条正文读取都会带上同一份全文身份。已经展开的长正文只在会话、消息或全文身份变化后重新加载；身份相同的新对象不重新请求。返回内容必须对得上当前身份，晚到的旧响应不能覆盖显示，也不能被复制。局域网 HTTP 页面没有 SubtleCrypto 时，仍用同一 SHA-256 算法核对全文，不改网络设置。实现有离线模型、预算、取消、恢复及临时本机 HTTP/CLI 回归，不代表真实模型的表达质量已验收；无需新增设置项或改变公开 API。
