# 桌面语音助手

在设置中打开独立的“语音助手”页面。后台唤醒默认关闭，未启用时不创建后台音频宿主、不自动下载模型、不持续占用麦克风。聊天里的手动听写只在用户按住时单独采集。开启后台助手后，在桌面进程内启动独立的音频窗口和使用随包 Node 运行的 sherpa-onnx 工作进程，主聊天窗口隐藏后继续运行。彻底退出或关闭后台开关销毁后台音频宿主和工作进程；后台聊天服务可以继续运行。正在主动使用的聊天听写完成或取消后释放其设备与推理资源。

## 首次配置

1. 打开顶部“启用语音助手”开关，立即生效；关闭时隐藏后续配置，并释放麦克风。“收听唤醒”和“自动播报”开关也立即生效；其他字段通过“保存语音设置”保存。
2. 在默认的“模型配置”标签页，先点击“下载唤醒与声纹模型”（约 73 MB）。包含固定版本的中英双语 KWS、Silero VAD 和 3D-Speaker ERes2Net，不包含识别或播报模型。
3. 分别点击“一键安装识别模型”和“一键安装播报模型”，无需先填写服务地址、模型名或 API Key。完成后直接选中本地运行方式。也可以在“连接已有服务”中配置各自的 OpenAI 兼容服务。
4. 切换到“唤醒与声纹”标签页，配置名字（默认 Pulse）和麦克风，保存；启动后台时授予实际运行的 Pulse 麦克风权限。
5. 点击“录入声纹”，连续说至少两秒后停顿。保存的是本机特征向量，不保存录音；可删除。该校验只过滤误唤醒，不提供安全认证或替代操作审批。
6. 在“模型配置”中试听音色，再回到“唤醒与声纹”使用“录音测试”检查转写，然后叫出名字开始聊天。名字可用中文或词典收录的英文单词；中英混合名字中的单个字母（如“小P”）同时保留英文读音和常用中文读法。未收录的英文拼写会明确提示更换，不能保证任意英文专名的发音。

## 一键安装的本地识别与播报

默认只使用聊天的按住说话，不在后台持续占用麦克风。需要喊名字启动对话时，单独开启“后台名字唤醒”；该选择持久保存，关闭会释放后台麦克风。旧配置没有该字段时默认关闭。名字唤醒开启期间需要持续采集音频，系统会显示麦克风使用提示；该提示不会被隐藏。按住说话不需要唤醒模型或主人声纹，松开、取消或离开页面时立即停止采集，尚未完成的识别可继续处理已录到的片段。

长句听写约每 1.2 秒提交一次完整的当前语句快照，更新同一段草稿，不把每个片段追加成独立句子；停顿或松开时定稿。低速识别时限制排队并停止采集。输入音频缓冲为 1024 帧；本地识别器在手动输入开始时预加载，预加载不打开麦克风。

- 输入：[SenseVoice Small int8（2024-07-17）](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)，压缩包约 163 MB，支持中文、英文、粤语、日语和韩语。已安装的 Whisper Base 继续可用，点击“升级中文识别”后下载并校验新模型；失败保留旧模型。识别准确率仍受口音、噪声和设备影响。
- 本地识别默认固定中文并通过 OpenCC 输出简体；历史空语言配置也按此处理，不修改配置文件。可在“模型配置 → 模型参数 → 识别语言”明确选择繁体中文、英文或自动检测；自动检测保留模型原文。外部服务的空语言配置仍由服务自动识别。
- 输出：Kokoro v1.0 中英双语 FP32 标准音质，压缩包约 350 MB。默认“晓北”中文女声，可直接选择多种中文男女声和 Heart 英文女声。已安装的 132 MB int8 紧凑版仍可使用，通过“升级播报音质”替换；升级保留已选音色，失败保留原模型。FP32 在本机样本对比中合成更快、高频杂音更低；不同设备仍需试听验证。
- 首次下载从 [sherpa-onnx 官方模型发布页](https://github.com/k2-fsa/sherpa-onnx/releases)获取固定模型，检查大小和 SHA-256 后安全解压，并保存逐文件校验记录。展示下载进度；超时、校验或加载失败可重试。中断的安装不会作为已就绪模型使用。识别及播报压缩包合计约 558 MB，完整解压及安装临时空间还需额外预留。
- 下载后由随包的 sherpa-onnx 与独立 Node 工作进程执行本机推理，不依赖 Python、Ollama、Speaches 或全局命令，不监听额外端口。后续启动自动检查已装模型；测试、转写与播报按各自保存的运行方式调用，支持本地与外部服务混用。网页端不能执行桌面本地模型。
- 安装动作只保存所选输入/输出连接，不提交其他尚未完成的设置草稿。选择本地模型保留已有服务地址及已保存的密钥引用；切回已有服务后重新选择其模型和音色。
- 关闭开关停止音频采集和推理进程；正在安装的下载可完成后退出。彻底退出会终止下载和工作进程，模型留在桌面用户数据目录的 `voice/speech-models/`，下次可以重试。关闭聊天窗口不停止已启用的助手。
- 模型无需 API 调用费用。SenseVoice 安装保留上游归属文件，并附带 [FunASR 模型许可证](https://github.com/modelscope/FunASR/blob/main/MODEL_LICENSE)；旧 Whisper 安装保留其 MIT 许可证。Kokoro 压缩包保留其 Apache-2.0 许可证、词典及归属文件。OpenCC 随桌面依赖保留 MIT 与字典的 Apache-2.0 许可证。音色 ID 依据 [sherpa-onnx 官方映射](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)。

“唤醒与声纹”页显示麦克风采样时长、当前输入强度和峰值，用于区分未收到音频、输入静音和名字/声纹未匹配。输入强度不表示唤醒或声纹识别已通过。

未唤醒音频仅在本机内存中短暂缓冲。每次语句通过声纹验证后才发送给所选 ASR；手动“录音五秒并转写”测试由用户直接触发，会把这五秒测试音频发送至 ASR。录入声纹完全在本机。

名字唤醒使用本地关键词时间戳，切除唤醒词录音后再转写指令，避免名字的识别错字混入聊天。只叫名字会进入等待指令状态，不创建聊天消息。短暂的前置缓冲避免 VAD 裁掉名字开头；每段关键词识别独立计时，长时间待机后仍按本段录音定位。ASR 仍可能识别错其他词语；录音切除位置和声纹过滤须通过真实发音、噪声环境验收。

## 聊天中的按住听写

聊天输入框长按后开始听写；也可以按住输入框右侧的麦克风按钮，或聚焦该按钮后按住空格/回车。普通点击、右键和移动拖选文字不启动录音。使用“语音助手”设置中保存的麦克风和识别模型，不要求开启后台唤醒、叫名字或录入声纹；本地 ASR 仍须在桌面客户端安装，网页端可使用已配置的兼容识别服务，且需要 HTTPS 或 localhost 的麦克风能力。

录音时持续将识别结果写入当前草稿：长句定时更新临时文字，停顿后以完整结果校正原位置，保留原有富文本、附件和文字。松开后立即释放采集设备并补齐最后一段；等待识别完成后可编辑、手动发送。听写不会自动发送聊天或触发播报，发送仍走原文字入口。录音/转写期间暂时禁用编辑和发送，避免迟到结果覆盖后续编辑。识别速度赶不上录音时停止采集并处理已有队列，不无限堆积。

Esc 或“取消”停止本次听写并忽略迟到结果；已显示的文字保留。切换会话、离开页面、隐藏窗口或权限/设备错误会释放设备，不把结果写入别的草稿。默认不保存原始录音。桌面听写期间由短期租约让后台唤醒释放麦克风、停止播报并暂停识别提交；结束后按原开关状态恢复，不修改启用或暂停偏好，也不取消已有聊天任务。页面异常退出时租约到期回收。

## ASR / TTS

ASR 使用 `POST /audio/transcriptions`，multipart 中包含 `model`、WAV 文件以及可选 `language`。TTS 使用 `POST /audio/speech`，JSON 中包含 `model`、`voice`、`speed`、`input` 和 `response_format: wav`。API Key 通过现有 ProviderCredentialStore 单独保存，配置只持有引用；不回显密钥。兼容服务需支持这些接口，不仅是聊天 completions 接口。

可用连接测试列出模型、录音转写测试及音色试听核对服务。试听不创建聊天；文字输入不会自动播报。“收听唤醒”关闭后释放麦克风，打开后恢复；“自动播报”默认开启且会保存偏好，关闭时立即停止当前播放，后续语音回复仅显示文字。切换播报不会重启麦克风、保存其他草稿或取消聊天任务；重新开启不会补播已停止的回复。语音回复仅播报关联到该语音请求的最终用户回复，去除代码块和 Markdown 标记，完整文字仍在聊天中。工具结果、内部推理和预回复不播报。

播报按完整句子依次合成、依次播放：首句合成好就播放，同时预合成下一句；最多保留正在播放的一句和下一句，不按固定字数截断。小数、常见英文缩写和闭合引号保留在原句中。全部句子播放完才打开追问窗口。音频合成完成不等于播放完成；合成/播放期间若连续三分钟没有有效进度或最终完成回执，会停止该段播报并明确提示“播放完成未确认”，不会假报成功、重播或取消聊天任务。停止、静音或新发言会丢弃旧回复的待播句子和迟到结果，不取消聊天任务；播放失败显示状态，不重新播放已播句子。长句仍须等整句合成完成才开始该句。

回复播放结束后默认保留 30 秒追问窗口。说“停止 / stop”停止播报，说“结束对话 / goodbye”结束连续语音；都不取消已经提交的后台任务，但会丢弃尚未提交的识别结果和排队语句，避免结束对话后迟到执行。新主人语句会中断当前播报，即使长回复已经超过普通追问窗口；播报期间的打断资格会在播放结束、停止或失败时清除，普通追问仍按原来的时限结束。音频宿主使用回声消除、降噪和声纹过滤；实际回声效果仍依赖设备，需进行真实麦克风验收。设备断开、权限拒绝或工作进程退出会停止设备并显示错误，由设置中的“恢复收听”重试，不反复打开设备。

## Speaches 本地示例

按 [Speaches 官方文档](https://speaches.ai/)安装独立服务，CPU 示例环境：

```sh
HF_HUB_DISABLE_XET=1 \
WHISPER__INFERENCE_DEVICE=cpu WHISPER__COMPUTE_TYPE=int8 \
ENABLE_UI=false uvicorn --factory --host 127.0.0.1 --port 8000 speaches.main:create_app
```

ASR 需要系统可执行的 `ffmpeg`（在服务进程的 PATH 中）。需要先安装模型；例如：

```sh
curl -X POST http://127.0.0.1:8000/v1/models/Systran/faster-whisper-tiny
curl -X POST http://127.0.0.1:8000/v1/models/speaches-ai/Kokoro-82M-v1.0-ONNX
```

填写 `http://127.0.0.1:8000/v1`，ASR 模型 `Systran/faster-whisper-tiny`，TTS 模型 `speaches-ai/Kokoro-82M-v1.0-ONNX`，英文音色 `af_heart`。中文要另选服务支持的中文模型/音色并试听，不能用英文试听成功推断中文支持。源码安装的 Speaches 还需要其静态资源目录；以所用版本的官方部署方式为准。

开发验收应使用独立数据目录；录音、声纹、模型缓存和本机验收记录仅保存在本地，不随源码分发。预录音频测试不能代替真人麦克风、回声和多人环境验收。

开发启动脚本自动传入 `PULSE_VOICE_NODE` 指向当前独立 Node；直接启动 Electron 时需手动设置该路径。原生推理不在 Electron V8 内运行，工作进程通过 JSON IPC 通信，避免不同 V8 版本的外部缓冲与序列化兼容问题。
