# 托盘后台与任务通知

Pulse 桌面端复用 Electron 主进程管理托盘，复用既有 `pulse h5 start` 后台。后台同时提供 server/API 和 Web/H5；CLI 是一个单独的交互终端，不作为重复的后台 server 启动。不会安装开机启动项或操作系统常驻服务。

## 使用

- 在仓库运行 `pnpm desktop:app:dev`。关闭桌面窗口会隐藏到托盘；后台任务与通知继续工作。
- 仅使用 H5：`pnpm desktop:app:dev -- --background`，再通过托盘的“打开 H5”使用浏览器。此时桌面窗口初始隐藏，可随时从托盘打开。
- 托盘菜单提供打开桌面端、H5、交互式 CLI、待处理问题/审批、最近结束的任务，以及启动/连接和停止后台。
- “退出托盘（保留后台服务）”会结束桌面端与通知接收器，后台继续。再次启动后连接已有后台。
- “停止后台并退出…”需要确认，会中断正在执行的任务。只有本托盘启动并核验实例身份的后台能被停止；外部入口启动的服务应在原入口停止。
- macOS 可在应用菜单“Pulse → 后台与通知菜单…”打开同一托盘菜单。
- 不会默认开放公网。新后台仍监听 `127.0.0.1`，复用原有设备配对和配置流程。
- 此处 H5-only 指本机浏览器使用：不需要显示桌面窗口，但托盘仍负责后台管理和桌面通知。`127.0.0.1` 不是手机可访问的局域网地址；手机需要已有、由用户另行配置为可达的 H5 服务及原有配对流程。托盘不会自动改监听地址、网络设置或安装远程推送。

## 通知与作答

H5/server 承接的任务，以及同数据目录中的交互式 CLI、`pulse run` 和非交互 resume 任务，会写入统一通知收件箱。CLI 复用既有 ConversationData 单写者服务，按运行发布状态，并通过同一服务收取定向回复，不新增端口或凭据。从托盘打开的 CLI 使用同一数据目录；独立启动时须选择相同 `PULSE_DATA_DIR` 或 `--data-dir`。CLI 自己的终端仍需保持运行，退出托盘不意味着托管了 CLI 进程。

有效待办独立保留，只有已结束历史限制为最近 200 条；回答、取消或运行失效后清除对应待办，服务重启时重新校验遗留问题。原有数组格式可直接读取。收件箱不复制问题正文或任务输出。桌面主进程每 2 秒同步，不依赖当前选中的会话或窗口可见状态；浏览器页面每 5 秒同步。完成通知以 run ID 去重，首次连接将既有完成任务设为基线，避免历史通知集中弹出。

CLI 桥按 run/conversation/group/effect 绑定，回复回执按 request ID 去重，每个运行最多保留 100 条桥接回执；未接收的回复 8 秒后过期，CLI 心跳失联 15 秒后视为中断，不能继续作答。H5 可在原工作会话展示问题并批量提交选择题、多题或审批；CLI 收到网页/通知回复后会清除终端的对应问题。非交互 `pulse run`/resume 保留既有遇到待输入立即取消的语义，通知不会让其变成交互终端。纯 CLI 且未运行 H5 服务/托盘时不会弹出桌面通知。

H5 成功接管中断的 CLI 运行后，保留原 CLI 快照并标记其已被接管，状态查询和通知同步不再使用该旧快照；标记跨服务重启保留。之后由 CLI 再次合法接管时，会发布新快照。用户确认停止托盘后台后，监控忽略已在途的探测结果，并等待先前已开始的连接流程结束再停止服务，避免自动重连重新拉起后台。

macOS 桌面通知对**单个文本输入问题**提供通知内回复。提交前重新读取对应 run/group/effect 状态，并通过原有批量问答接口发送；重试使用固定 request ID。过期、已回答和已结束问题不接受新的回答。短普通单选可使用系统按钮；多题、长选项和多选打开独立问答小窗，审批进入完整会话。通知关闭或超时不会回答或批准。

普通问题点击通知打开绑定原题组的小窗，完成通知和正式审批打开完整会话。默认系统通知隐藏任务输出；短单选显示必要题目与选项，其他问题正文在小窗查看。系统通知失败或权限被拒绝时保留托盘待办和最近任务，不循环请求权限。

H5 页面右上角“通知 / 待办”可在用户点击“启用系统通知”后请求浏览器权限。浏览器权限被拒绝或没有 Notification API 时，仍可从此入口进入任务；H5 未实现通知内文本回复，点击进入任务并聚焦问题。没有 Service Worker/Web Push，因此浏览器完全退出后不会接收系统通知；需要持续通知时保留桌面托盘。

开发启动仍使用 npm Electron 身份，不应把其通知表现等同正式 Pulse 包。正式构建已有 productName=Pulse、稳定 appId 与现有品牌 icns。真正发起屏幕录制/辅助功能权限的 Swift helper 现在也在产品构建中写入 CFBundleName/DisplayName=Pulse 与同一 icns，保持既有内部文件名及 bundle ID。旧系统列表可能缓存 Helper 名称/图标；新构建不会自动清除旧记录或代替用户重新授权。

## 通知单选与问答小窗（2026-10-26 新增）

macOS 正常签名且 Info.plist 配置 `NSUserNotificationAlertStyle=alert` 时，单道普通单选、最多3个短选项（各18个 Unicode 字符内）、题目140字符内且无选项说明，可映射原生 action 按钮。通知显示该短题与完整选项标签，便于明确作答；不显示其他任务输出。长题、长选项、说明、多题和多选不截断为按钮，点击打开独立问答小窗。系统若不显示按钮，同一通知点击及托盘/应用菜单待办也可打开小窗。未自动改变用户系统通知样式；系统最终决定按钮是否显示。

单文本继续使用 `hasReply`，不混入 action；多选小窗含复选框和明确提交，多题必须全部有效后一次提交，长题/选项可滚动，支持键盘焦点和 Escape 关闭。关闭、取消窗口不发送 dismissed、答案或审批；重新打开同题可恢复草稿。草稿按 run/group/题目版本隔离。

每个小窗只绑定一个捕获的 run/conversation/group/effect 集合，使用专用最小 preload；读取和提交前刷新原题组及输入指纹，已答/变更/取消显示失效，不切其他问题。重复提交复用稳定 request ID。审批、计划执行确认以及其他正式决策仍打开完整会话，不提供通知内批准或轻量批准。H5/浏览器通知仍回原页面，不能称浏览器支持通知内复选表单。

独立签名包实测：多选甲/丙及第二题 window-ok 完整提交，经原 CLI 桥进入 succeeded；关闭重开保留未提交选择，附实机截图与回执。原生短单选通知已送达，按钮显示/点击回执仍待实际用户确认，不能以 mock action 测试或系统送达记录代替。官方限制：https://www.electronjs.org/docs/latest/api/structures/notification-action 。

### 用户实测后的窗口行为修正

2026-10-26 用户确认两项缺陷：成功提交只显示“已提交”而未关窗，通知激活会先显示主面板。已在源码修正：收到后台成功回执后只关闭原提交窗口；失败/未确认保留草稿；晚到响应不关闭重开或其他题目的窗口。activate/second-instance 在通知启动、待答或已有小窗时不抢开主面板；通知冷启动使用 ready 的 NotificationResponse 定位原通知，主窗初始隐藏。仍可从“显示 Pulse”显式打开主面板。

相关20项回归通过。本轮15分钟有界验收未记录到实际点击或答案，已自然结束并确认测试 Electron/服务退出；真实通知直达和提交自动关窗仍未实机通过。此前多选答案传输成功不代表完整窗口交互已通过。不会自动重复发题。


## 恢复预检、离线更新进度与本地诊断（2026-10-26）

- 中断任务点击“继续任务”先读取恢复预检。同构建无需构建确认；跨构建展示完整运行 ID 和旧、新构建指纹，只有用户明确确认才向该次恢复传递精确构建对。取消、切换会话和过期确认不会自动继续。实际恢复仍执行原有工具、策略、数据和所有权检查；预检不激活工具。策略不兼容、快照缺失/不可读/格式冲突会显示阻塞原因，原数据保留。
- 后台离线时的独立更新控制进程与状态查询共享本地进度日志，沿用 UpdateStatus.progress。每次下载使用独立 ID，最多每 250ms 写一次，按组件切换；60 秒未更新的百分比隐藏，下载终态清理本次日志。旧回调和旧清理不会修改新下载。无需额外服务或实际下载才能查询进度。
- 桌面菜单“查看后台启动诊断…”或“桌面环境 → 查看启动诊断”可读取本机日志，后台不可用时也可用。桌面记录启动错误及退出码；桌面启动的后台自身记录输出和退出，关闭主窗口不会停止日志。日志只留本地，不上传；使用现有凭据脱敏，跨输出块先拼行，私钥块及超长行整段省略。每个日志最多 64KiB（另留一份轮转），整体最多 8 个文件，界面最多读取最近 4 个文件的有限尾部。外部入口启动的后台仍在原入口查看日志。

本轮只执行模拟恢复确认、隔离本机 HTTP、临时文件和独立 Node 进程读取测试。没有迁移或恢复用户任务，没有实际下载/安装更新，没有启动新的系统通知验收轮次。

### 跨端问题通知清理

问题在 H5、CLI 或其他窗口答完、取消或失效后，桌面下一次成功同步会关闭对应系统问题通知；后台暂时不可达时保留现状。问题通知以原 run/group 和题目指纹区分，同一逻辑位置出现新问题时，旧通知和迟到的旧回执不会关闭新题。重启时重新核对系统通知历史，只恢复仍有效且指纹一致的问题；完成通知历史独立保留。

升级前没有题目指纹的旧问题通知会在首次成功同步时撤销，仍待回答的问题可重新显示一次。撤销、关闭通知或网络超时均不表示提交答案或批准。
