# 安全自举与运行版本切换

自举要区分代码修复、合入和运行版本切换。模型报告完成不能代替固定检查通过，合入成功也不代表后台已经运行新版本。

## 隔离修复与自动合入

使用 `scripts/self-host.mjs --transport h5`，参数由 `--help` 查看。稳定 CLI 入口必须位于候选项目之外；已有代码胶囊不会自动随源码升级。`scripts/self-host-snapshot.mjs` 可从已构建的 CLI 创建新的外部胶囊并验证其完整性，目标必须尚不存在，不覆盖旧胶囊。

H5 服务和稳定引擎都必须支持新的外部门禁协议：

1. 监督器认证后先核对 `/api/session` 的 `selfHostExternalValidation` 能力。旧服务不支持时，在创建修复任务之前停止。连接失败也不会静默降级为直接修改原目录的 CLI。
2. 新会话显式声明 `selfHostExternalValidation: true`，由本机管理员同源请求创建独立 Git 工作区。不支持隔离的目录拒绝此模式。
3. 会话记录持久保留外部门禁标记。服务收到模型 `accepted` 后只保留候选，不自动应用到原项目；重启及同会话后续修复也不取消此标记。
4. 监督器读取本次 conversation/run 的验收文件，再执行调用者固定的原始检查 argv。任务、检查清单及额外冻结文件不可修改。候选目录内对应的冻结文件也必须一致。
5. 候选检查全部通过后，稳定引擎的 `finishVerified` 在新的集成目录合并候选与当前用户改动，重新运行同一套固定检查。检查失败、冻结文件不一致、检查期间源码变化均拒绝应用。旧稳定引擎缺少此接口时停止，不退回无验证合入。
6. 通过集成验证且原项目未变化时才应用补丁，保留用户原有暂存区；随后对原项目再执行相同检查。并发用户修改会触发重新集成和验证；另一合入持锁时返回冲突，保留候选。

报告保留基线、每轮真实检查、集成检查、原项目复检及会话/run 身份。失败记录不能由下一轮修复抹除。检查失败后的下一轮使用同一会话，并收到原始退出码和日志尾部。

`--transport cli` 保持现有直接修复工作区的模式，不提供上述 H5 隔离合入保证。需要安全自动合入时应明确使用 H5 模式。

## 自动切换的目标与边界

运行版本切换应复用 [分模块更新](updates.md) 的稳定启动器、空闲维护门禁、独立版本目录、健康检查及失败恢复，不能简单地把正在运行的源码目录替换掉。

- 首先明确目标是托管后台、源码开发 H5 还是桌面壳，以及其实际启动器和运行目录。未确认具体目标时，只完成代码验证和合入，不修改当前服务、持久启动器或安全设置。
- 托管更新器仍验证组件签名、完整文件摘要、数据与协议兼容性。源码自举产物不能伪装为已签名发布组件；生成或公开发布组件需要另外的发布授权。
- 既有托管后台在空闲维护租约下由协调器停止它自己创建的子进程，候选健康后更新活动选择；失败恢复原代码版本，不用旧数据库覆盖用户数据。更新中断由切换日志在下次启动时恢复。
- 桌面壳安装、首次把旧服务接入托管启动器，以及其他持久服务或安全设置变更应单独确认具体目标和动作。

本实现不新增任意 shell 激活钩子，也不会因合入通过就绕过签名、空闲门禁或启动另一份真实数据服务。


## 稳定引擎预检与胶囊身份

修复前先做只读预检，再执行基线检查。H5 模式在认证、创建会话或调用模型之前核验稳定引擎 `get`、`close`、`finishVerified` 接口及 `selfHostBeforeApply = 1` 能力；预检不实例化 workspace manager，不打开任务数据。旧胶囊缺少接口或提交前中断门禁时直接停止。实际模块先解析真实路径、检查目录边界并固定文件摘要，再载入并立即复验。

新快照清单增加 `runtimeIdentity`，`runtimeDigest` 绑定运行文件及其权限、内部链接、入口、依赖节点与边、布局和数据复制策略。创建时间、来源说明等非运行元数据不参与摘要；依赖包实际目录名仍属于运行身份。这个摘要证明运行闭包身份，不是源码提交、源码 CI 或服务已经运行的证明。

- `self-host-snapshot.mjs verify --snapshot <dir> --expected-digest <sha256>` 可使用调用者独立保存的摘要验收胶囊。
- 快照生成的监督命令带有 `--engine-snapshot <dir> --engine-digest <sha256>`。代码和清单一起被替换也不能通过原摘要。
- 未显式指定目录时，监督器从 CLI 入口向上查找快照清单；发现清单就完整校验，不能静默降级到只核验入口。
- 已确定的运行摘要在修复调用前后、合入前的集成验证结束时和最终成功前复验。候选模块不能通过链接越出胶囊或指向正在修复的目录。
- 兼容没有快照清单的稳定安装，但报告明确为 `entry-only` 或 `entry-and-workspace-module`，不承诺其全部传递依赖已经隔离。完整闭包保证应使用胶囊。
- 旧版 v1 清单仍可验证并计算摘要；有 `runtimeIdentity` 的清单必须与计算结果一致。调用者未独立提供摘要时，报告 `externallyPinned: false`。

摘要必须由可信的监督器/验证工具核对。胶囊内的监督脚本不能自行证明它自己未被整体替换；不要把这种本地完整性检查当成发布签名或额外信任授权。

## 阶段报告

`report.json` 的 schemaVersion 为 2，保留已有字段，并增加 `engineIdentity`、只追加的 `stages` 和 `delivery`。每个重要阶段以原子文件替换持续保存，包括预检、基线、修复、候选检查、集成检查、合入及原目录复检。

`delivery.merge` 独立于最终成功状态。补丁已应用但后续引擎复验或 manager 收尾失败时，仍记录 `merged`，不能误报为尚未合入；集成验证回调拒绝时记录 `blocked`。若 manager 在可能已应用补丁之后、返回确认之前抛错，则记录 `unknown` 与 `needs_attention`，停止自动重试，不能断言没有合入。历史失败与阶段记录不会由下一轮修复擦除。

本阶段不激活运行版本：报告始终明确 `activation: not_requested`、`runningVersionVerified: false`。制作新胶囊或全部代码检查通过，都不代表后台、Vite 或桌面壳已经切换。

## 中断与合入结果不确定

监督器在候选检查结束、集成检查结束及真正启动 Git apply 之前检查中断状态。收到 SIGINT/SIGTERM 后不再开始尚未执行的合入；各阶段固定检查超时均记录为 timeout，不混同普通检查失败。已经开始的 Git 写入不能承诺跨文件崩溃原子性，也不能用自动反向补丁覆盖用户并发工作。

- Git 合入先持久记录 `mergeState: applying`。补丁应用或最终状态保存失败时保留该标记；重启后的同一工作区拒绝自动重试，也不继续新修复，要求先核对项目与候选。
- 合入锁内重新读取工作区状态，避免迟到的任务完成回调把 merged 改回 pending。
- 活跃或遗留合入锁均不自动抢占。单一 PID 不能可靠排除跨机器或 PID 复用，强杀后的锁会明确阻塞，需核对现场后处理。
- 提交前门禁拒绝时可明确记录未应用；如果补丁可能已应用但没有确认，报告保留 unknown/needs_attention。已经确认合入后，原目录复检失败仍如实记录 merged/project_failed。

这些是源码合入的安全边界，不是运行服务的自动切换或回滚实现。

## 隔离运行切换实验

新增 [隔离运行版本切换实验](self-host-runtime.md)，在全新合成 home/data/state 中管理自己启动的真实协作进程，验证摘要、实例身份、空闲门禁、健康与失败恢复。它不接管现有服务，不修改签名更新路径；主自举合入仍不自动激活运行版本。

## 内部数据与 Git 历史防线

H5 自举要求稳定引擎和正在运行的 H5 服务均声明 `selfHostInternalDataBoundary = 1`。旧胶囊、旧服务会在创建修复任务前被拒绝；仅更新源码不会升级已有运行代码，必须重新构建并创建新胶囊，旧胶囊不被覆盖。

该模式在新建、恢复候选和验证合入时检查 `.pulse`、`.pulse-*` 及配置的 data-dir。发现内部文件（包括被忽略的文件）、被 Git 跟踪的内部路径，或祖先、其他引用、reflog 中的相关历史时拒绝操作。只有当前 manager 自己的未跟踪 workspaces 运行目录被排除；已经跟踪的 workspaces 不豁免。浅克隆、部分克隆、替换对象、grafts、外部对象库或检查失败也拒绝，不联网补取历史。

- `SELF_HOST_INTERNAL_DATA_PRESENT`：存在已识别的内部数据，候选创建或合入被阻止。
- `SELF_HOST_INTERNAL_HISTORY_PRESENT`：可检查的 Git 历史包含受保护路径。当前树删除文件或添加忽略规则不能消除这个问题。
- `SELF_HOST_HISTORY_UNVERIFIABLE`：无法可靠完成上述检查。

这是保守的已知路径防线，**不是 Git 对象库隔离，也不是 OS 沙盒**。linked worktree 仍共享原仓库对象；其他名称下的数据、无引用的对象和不属于上述路径的其他引用不在保密保证内。不要用这种模式处理需要强保密隔离的仓库。含内部数据的敏感场景应使用另建的、只包含明确允许代码的独立仓库与外置 data-dir，不能只复制 `.git` 或把工作目录换成另一个 worktree。

防线不删除文件、不清理或重写原历史、不改用户暂存区。它可能阻止以前可运行的自举任务，尤其是代码旁同时存放真实 Pulse 数据的目录。普通非自举任务的工作区行为不受此门禁改变。完整修复仍需独立对象库、无历史代码快照和经验证的补丁回写方案。

### 新建 H5 自举任务的外置文件历史

新建 H5 自举会话会在准备候选之前，把“必须使用外置文件历史”的标记写入初始 manifest。文件快照、WAL、已提交历史和回滚日志保存在 `dataDir/self-host-file-history/<conversationId>`，必须位于整个原仓库与候选工作区之外。版本化 manifest 绑定与独占创建的 `binding.json` 共同记录会话、候选和项目的真实路径，以及候选目录的 device/inode 身份。存储缺失、绑定不符、符号链接、目录被替换或嵌入代码树时均拒绝操作；中断的存储初始化不自动接管、重试或迁移。

首次执行、重启、WAL 确认与恢复、明确限定会话范围的回滚都选择同一份经过验证的存储。候选缺失、被替换、已完成合入或被切换到其他工作区时，不允许把恢复目标改成原项目。合入或删除候选后保留历史，但不能据此自动回滚原项目，也不回退或复制到项目内的 `.pulse`。在有明确的绑定保留协议之前，这类会话的导出与转移会被拒绝。普通任务继续使用原存储方式；旧任务和候选内已有历史不自动迁移或删除，仍由内部数据防线拦截。

这些检查提供的是存储与恢复绑定的失败关闭保护，不是对恶意本机进程的隔离。linked worktree 仍共享 Git 对象库和文件系统权限。
