# 计划自洽复核

需要执行确认的规划任务（包括 `/grill-and-plan`）在保存或修改 `docs/plans/*.md` 后，会独立复核整份文件。复核使用现有 `verify` 模型路由，计入该任务的模型调用预算；不复用作者对本次修改的自我评价。

复核覆盖步骤与前置条件的依赖关系、未解决的实施条件、状态与交互规则、已确认范围及验收安排。输入包含完整计划、近期用户要求、已确认问答和 Host 实际测试保护信息。模型给出原文引用和依赖图，Host 再检查检查项覆盖、引用真实性、缺失依赖、循环依赖及未解决条件。

通过结果绑定当前运行、文件路径和内容 hash。结果保存在运行目录的 `plan-reviews` 下，并随文件写入回执返回给 Agent。只改一段内容也会重新复核整份计划，旧版本的复核或执行许可不能授权新版本。

未通过时不提供执行确认，而是反馈具体问题供修订；真实的外部阻塞应如实报告并保留计划。复核不可用、输出不完整或证据不匹配也不能放行。`plan.review` 可重新读取保存的计划并复核。用户的执行确认仍然必须单独获得。

冷启动恢复保留已有复核结果；缺少复核的旧运行不能直接凭旧确认开始实施。外部改动导致 hash 变化时，也需要重新复核和确认。

依赖图中的循环由代码检查；自然语言矛盾及依赖关系的提取仍依赖模型判断。这一流程不保证发现所有语义问题，也不替代代码审查或实际验收。它不解除既有测试保护或自动解决缺失的授权机制。
