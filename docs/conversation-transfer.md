# 工作会话导出与跨机恢复

在“工作”界面点击顶部“导出”，即可下载当前会话的 ZIP。运行中（包括等待交互时）不能导出；请等待任务完成，或在原进程中断后导出。正常取消或关闭产生的已结束任务只能查看历史，不能作为断点续跑。

压缩包包含聊天 Markdown、结构化消息、附件及各次运行的恢复数据和调试记录。JSON、SQLite 和外置文件存储均受支持。SQLite 使用包含 WAL 数据的一致性副本。项目源码、全局配置和服务认证不随会话迁移；上传附件保留原始文件内容。

## 导入

1. 自行将源机器的执行目录内容同步到目标机，包含尚未提交的项目修改。源任务如使用隔离工作区，以实际执行目录内容为准。
2. 在目标机历史会话栏点击“导入会话”，选择 ZIP。
3. 选择已经注册的本机项目，查看恢复检查结果，点击“导入并查看”。导入不会自动执行任务，也不覆盖已有会话。
4. 对可恢复的中断任务，点击现有“继续任务”按钮，重新确认待审批操作。执行前会再次检查项目状态和工具契约；Git 项目重新建立本机隔离工作区。

相同 ZIP 的重复导入会打开原导入会话；其他同 ID 会话或运行记录发生冲突时拒绝覆盖。临时上传保留十分钟，取消、失败或服务正常停止时清理。

## 恢复条件

- 两台机器使用相同 Pulse 构建，而不仅是相同版本号；原模型须在目标机有可用配置。
- 工具契约、权限和网络策略兼容，目标机采用逐项审批。
- 项目文件指纹一致，快照和外置引用完整。文件指纹目前受既有边界限制：需要 Git 项目，最多 5,000 个文件、单文件 8 MB、总计 64 MB；超限时仍可导入调试资料。
- 不重放已完成的工具操作，不重置累计预算，不沿用源机器授权。存在结果未知的副作用、未完成的浏览器/桌面操作、无法迁移的绝对命令路径等情况时阻止恢复。
- 消息与文本调试记录会脱敏。若恢复状态本身因敏感信息而改变，会明确阻止断点恢复，不绕过快照完整性校验。

受阻会话仍保留聊天、附件和调试记录。环境差异在下一次恢复前重新检查；修复项目同步或模型配置后可以重试。无法恢复原任务时，可结束该轮，再发送新消息。

## 文件格式与接口

ZIP v1 包含 `bundle.json`（版本、来源、文件大小、SHA-256 清单）、`chat.md`、`README.txt`、`conversation/` 和可选 `diagnostics/`。历史审批、计划授权和 Jarvis 同步身份仅用于排查，不恢复为本机权限。

- `POST /api/conversations/:id/export`：返回 `application/zip`。
- `POST /api/conversation-imports`：上传原始 ZIP，返回有设备归属和有效期的预览 token。
- `POST /api/conversation-imports/:token`：`{ projectId, preview: true }` 检查绑定；`{ projectId }` 确认导入。
- `DELETE /api/conversation-imports/:token`：取消上传。

接口要求已认证设备和同源请求。限制：ZIP 256 MiB、解压后 1 GiB、20,000 个条目、单条目 128 MiB；拒绝路径穿越、链接、加密条目、大小写冲突和清单校验失败。
